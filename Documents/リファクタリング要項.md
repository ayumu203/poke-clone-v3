## 4. パフォーマンス改善

### 4.1 不要な再レンダリング

**問題箇所**: `useAuth.ts` (L18-76) の `useEffect` が認証状態変化時に大量の処理を実行。

**改善案**: プレイヤー作成処理を別のhookに分離し、認証成功時のみ一度だけ実行させる。

---

### 4.2 useCallback/useMemo の活用

**問題箇所**: `BottomScreen.tsx` (L57-88) の `getBackgroundStyle` 関数がレンダリング毎に再生成される。

**改善案**: `useMemo` でメモ化。

```tsx
const backgroundStyle = useMemo(() => 
    getBackgroundStyle(backgroundImage, darkGrid), 
    [backgroundImage, darkGrid]
);
```

---

### 4.3 useApi の再生成問題

**問題箇所**: `usePokemonSpeciesBatch.ts` (L36-50)

```tsx
export function usePokemonSpeciesBatch(pokemonSpeciesIds: number[]) {
    const { request } = useApi<PokemonSpecies>();
    // ...
}
```

`usePokemonSpeciesBatch` を使用するたびに新しい `useApi` インスタンスが生成されます。

**改善案**: `useApi` をContext化するか、適切にメモ化する。

---

### 4.4 staleTime の設定

**問題箇所**: `useParty.ts` (L19)

```tsx
staleTime: 0, // キャッシュせず毎回取得
```

パーティ情報は頻繁に変わらないため、短いキャッシュ時間を設定することでAPIリクエスト頻度を削減可能。

**改善案**: `staleTime: 15 * 1000` (15秒) など適切な値を設定。

---

## 5. セキュリティ改善

### 5.1 IDトークンの直接公開

**問題箇所**: `useAuth.ts` で取得した IDトークンをそのまま使用。

**現状**: IDトークンは適切に `Authorization` ヘッダーに設定されており、httpOnly Cookie でセッション管理もされています。

**確認事項**:
- サーバー側で IDトークンの検証が適切に行われているか確認してください
- トークンのリフレッシュ処理が必要か検討してください

---

### 5.2 プレイヤー情報の自動作成

**問題箇所**: `useAuth.ts` (L39-62)

```tsx
if (checkResponse.status === 404) {
    console.log('プレイヤーアカウントを作成します...');
    const createResponse = await fetch(`${apiUrl}/api/Player/me`, { ... });
}
```

**リスク**: 認証に成功した全てのユーザーに対して自動的にプレイヤーアカウントを作成しています。

**改善案**: プレイヤー作成のタイミングを明示的に制御することを検討。

---

### 5.3 エラーメッセージの詳細

**問題箇所**: `useApi.ts` (L45)

```tsx
throw new Error(`HTTP ${response.status}: ${response.statusText}`);
```

**リスク**: HTTPステータスコードとステータステキストをそのままエラーメッセージに含めています。

**改善案**: ユーザー向けメッセージと開発者向けログを分離(環境変数IS_DEVELOPMENTを使用)。
