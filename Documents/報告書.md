## 1. セキュリティインシデント

### 🔴 Critical: Firebase APIキーの露出

**問題**:
- `.env.local`ファイルにFirebase APIキーが平文で記載されている
- このファイルが誤ってGitにコミットされるリスクがある
- 実際に`grep`で確認したところ、全ての認証情報が平文で存在

**発見箇所**:
```
Client/.env.local:
NEXT_PUBLIC_FIREBASE_API_KEY=AIzaSyCyioNuBh1prVDpTchaYAHkNIF0EEGGbko
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=poke-clone-v3.firebaseapp.com
... (その他の認証情報)
```

**影響**:
- 不正アクセスのリスク
- Firebase使用量の不正利用
- データベースへの不正アクセスの可能性

**推奨対策**:

> [!CAUTION]
> 直ちに対応が必要です

1. **即座の対応**:
   ```bash
   # .env.localを.gitignoreに追加（既に追加されているか確認）
   echo ".env.local" >> .gitignore
   
   # Gitの履歴から.env.localを完全削除
   git filter-branch --force --index-filter \
     "git rm --cached --ignore-unmatch Client/.env.local" \
     --prune-empty --tag-name-filter cat -- --all
   ```

2. **Firebase設定の見直し**:
   - Firebaseコンソールで**App Check**を有効化
   - **Security Rules**を適切に設定
   - **API制限**を設定（許可されたドメインのみ）

3. **環境変数テンプレート作成**:
   ```bash
   # .env.example を作成
   cp Client/.env.local Client/.env.example
   # 機密情報をプレースホルダーに置換
   ```

   export async function GET(request: Request) {
     const token = request.headers.get('Authorization')?.split('Bearer ')[1];
     
     try {
       const decodedToken = await verifyIdToken(token);
       return NextResponse.json({ valid: true, uid: decodedToken.uid });
     } catch (error) {
       return NextResponse.json({ valid: false }, { status: 401 });
     }
   }

## 2. コンポーネント設計の改善点

### 🟡 High: useAuthフックの責務過多

**問題**:
`useAuth.ts`が以下を全て担当している:
- 認証状態の監視
- ログイン/サインアップロジック
- セッションCookieの管理
- API呼び出し

**発見箇所**:
[useAuth.ts:15-147](file:///home/cs23017/poke-clone-v3/Client/src/hooks/useAuth.ts#L15-L147)

**影響**:
- テストが困難
- 再利用性の低下
- Single Responsibility Principleの違反

**推奨対策**:

1. **認証サービスの分離**:
   ```typescript
   // lib/auth/authService.ts
   export class AuthService {
     async loginWithEmail(email: string, password: string) {
       const userCredential = await signInWithEmailAndPassword(auth, email, password);
       return userCredential.user;
     }
     
     async loginWithGoogle() {
       const provider = new GoogleAuthProvider();
       const userCredential = await signInWithPopup(auth, provider);
       return userCredential.user;
     }
     
     async logout() {
       await signOut(auth);
     }
   }
   
   export const authService = new AuthService();
   ```

2. **セッション管理の分離**:
   ```typescript
   // lib/auth/sessionService.ts
   export class SessionService {
     async createSession(token: string) {
       await fetch('/api/auth/session', {
         method: 'POST',
         body: JSON.stringify({ token }),
       });
     }
     
     async destroySession() {
       await fetch('/api/auth/logout', { method: 'POST' });
     }
   }
   
   export const sessionService = new SessionService();
   ```

3. **useAuthフックの簡素化**:
   ```typescript
   // hooks/useAuth.ts
   export function useAuth() {
     const [user, setUser] = useState<User | null>(null);
     const [loading, setLoading] = useState(true);
     
     useEffect(() => {
       return onAuthStateChanged(auth, async (currentUser) => {
         setUser(currentUser);
         if (currentUser) {
           const token = await currentUser.getIdToken();
           await sessionService.createSession(token);
         } else {
           await sessionService.destroySession();
         }
         setLoading(false);
       });
     }, []);
     
     return {
       user,
       loading,
       isAuthenticated: !!user,
       loginWithEmail: authService.loginWithEmail,
       loginWithGoogle: authService.loginWithGoogle,
       logout: authService.logout,
     };
   }
   ```

### 🟢 Medium: Atomic Designパターンの不完全な実装

**問題**:
- `molecules`に2つのコンポーネントのみ（EmailLoginForm, StatusBar）
- `organisms`と`molecules`の境界が曖昧
- `pages`レベルのコンポーネント（実装予定.mdで言及）が未実装

**影響**:
- コンポーネントの階層が不明確
- 再利用性の低下
- 新規メンバーの理解が困難

**推奨対策**:

1. **コンポーネント配置の見直し**:
   ```
   components/
   ├── atoms/          # 最小単位（ボタン、入力、アイコンなど）
   ├── molecules/      # atomsを2-3個組み合わせた単位
   │   ├── PokemonCard/      # ポケモンの画像+名前+HPバー
   │   ├── MoveButton/       # 技名+PP+タイプアイコン
   │   └── PlayerInfo/       # アイコン+名前
   ├── organisms/      # 機能的なまとまり
   │   ├── BattleField/      # バトル画面全体
   │   ├── PartyList/        # パーティ一覧
   │   └── MoveSelector/     # 技選択UI
   └── templates/      # ページレイアウト
       ├── DSLayout/
       └── BattleLayout/
   ```

2. **コンポーネント分割の基準を明確化**:
   - **atoms**: 他のコンポーネントに依存しない
   - **molecules**: atomsのみに依存
   - **organisms**: atoms + moleculesに依存、ビジネスロジックを含む
   - **templates**: レイアウト構造のみ、具体的な内容を持たない

## 3. 実装の簡潔化

### 🟡 High: BGMContextのlocalStorage同期ロジックの重複

**問題**:
`BGMContext.tsx`で各状態ごとに個別のuseEffectを使用している

**発見箇所**:
```typescript:Client/src/contexts/BGMContext.tsx
useEffect(() => {
  localStorage.setItem('bgm-enabled', String(isBgmEnabled));
}, [isBgmEnabled]);

useEffect(() => {
  localStorage.setItem('bgm-volume', String(volume));
}, [volume]);
```

**推奨対策**:

1. **カスタムフックの作成**:
   ```typescript
   // hooks/useLocalStorage.ts
   export function useLocalStorage<T>(
     key: string,
     initialValue: T
   ): [T, (value: T) => void] {
     const [state, setState] = useState<T>(() => {
       if (typeof window === 'undefined') return initialValue;
       
       const stored = localStorage.getItem(key);
       return stored !== null ? JSON.parse(stored) : initialValue;
     });
     
     const setValue = useCallback((value: T) => {
       setState(value);
       localStorage.setItem(key, JSON.stringify(value));
     }, [key]);
     
     return [state, setValue];
   }
   ```

2. **BGMContextでの使用**:
   ```typescript
   export function BGMProvider({ children }: { children: ReactNode }) {
     const [isBgmEnabled, setIsBgmEnabled] = useLocalStorage('bgm-enabled', false);
     const [volume, setVolume] = useLocalStorage('bgm-volume', 50);
     
     return (
       <BGMContext.Provider value={{ isBgmEnabled, setIsBgmEnabled, volume, setVolume }}>
         {children}
       </BGMContext.Provider>
     );
   }
   ```

## 4. 状態管理の改善

### 🟡 High: グローバル状態管理の不在

**問題**:
- React QueryとContextを混在使用
- Zustand が導入されているが未使用
- バトル状態、プレイヤー情報の管理が各フックに分散

**推奨対策**:

1. **Zustandによるグローバル状態管理**:
   ```typescript
   // stores/battleStore.ts
   import { create } from 'zustand';
   import type { BattleState } from '@/types/battle';
   
   interface BattleStore {
     currentBattle: BattleState | null;
     setBattle: (battle: BattleState) => void;
     updatePokemonHp: (pokemonId: string, newHp: number) => void;
   }
   
   export const useBattleStore = create<BattleStore>((set) => ({
     currentBattle: null,
     setBattle: (battle) => set({ currentBattle: battle }),
     updatePokemonHp: (pokemonId, newHp) => set((state) => {
       if (!state.currentBattle) return state;
       // HP更新ロジック
       return { currentBattle: { ...state.currentBattle } };
     }),
   }));
   ```

2. **状態管理の役割分担を明確化**:
   - **React Query**: サーバー状態（API取得データ）
   - **Zustand**: クライアント状態（バトル進行、UI状態）
   - **Context**: テーマ、言語など変更頻度の低いグローバル設定
